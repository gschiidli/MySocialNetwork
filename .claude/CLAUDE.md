## Project Overview

MySocialNetwork is an iOS application for managing contacts and their relationships (family/social connections). Built with SwiftUI and The Composable Architecture (TCA), it uses SQLite for local persistence with CloudKit synchronization support.

- **Platform**: iOS 26+
- **Bundle ID**: `com.MySocialNetwork.app`
- **Swift Version**: 6.2

## Build System: Tuist

This project uses Tuist for Xcode project generation and dependency management.

### Key Tuist Commands

- `tuist generate` - Generate the Xcode workspace (required before opening in Xcode)
- `tuist build` - Build the project
- `tuist test` - Run unit tests
- `tuist run` - Build and run the app
- `tuist clean` - Clean build artifacts
- `tuist edit` - Generate a temporary project to edit Tuist manifests

**Important**: Always run `tuist generate` after modifying Project.swift, Tuist.swift, or any Package.swift in the Packages directory.

## Architecture: The Composable Architecture (TCA)

The app uses Point-Free's [Composable Architecture](https://github.com/pointfreeco/swift-composable-architecture) for state management.

### Key TCA Concepts Used

- **@Reducer** - Macro for defining feature reducers
- **@ObservableState** - Reactive state management
- **@Dependency** - Environment-based dependency injection
- **StackState/StackAction** - Type-safe navigation
- **Store** - Runtime container for state and actions

### Pattern Example

```swift
@Reducer
struct MyFeature {
  @ObservableState
  struct State: Equatable { ... }

  enum Action { ... }

  @Dependency(\.myClient) var myClient

  var body: some ReducerOf<Self> {
    Reduce { state, action in
      // Handle actions, return effects
    }
  }
}
```

## Feature Packages

### Models (`Packages/Models/`)
Shared domain models used across features.

- **Contact** - Represents a device contact with name and relations
- **ContactRelationship** - Database model for CloudKit-synced relationships between contacts

### ContactsClient (`Packages/ContactsClient/`)
Abstraction over the native Contacts framework for testability.

- **ContactsClient** - Interface with `fetchContacts()` and test implementation
- **ContactsClientLive** - Live implementation using CNContactStore

### AppFeature (`Packages/AppFeature/`)
Root feature managing the contacts list and navigation.

- Fetches contacts via ContactsClient
- Manages navigation stack to ContactDetailFeature
- Entry point: `AppView`

### ContactDetailFeature (`Packages/ContactDetailFeature/`)
Displays individual contact details and their relationships.

- Shows both CloudKit-synced and device contact relationships
- Queries ContactRelationship table from database
- Uses SQLiteData's `#sql` macro for type-safe queries

## Database

Uses GRDB via SQLiteData for local persistence.

### Schema

```sql
CREATE TABLE "contactRelationships" (
  "id" TEXT PRIMARY KEY NOT NULL DEFAULT (uuid()),
  "contactID1" TEXT NOT NULL,
  "contactID2" TEXT NOT NULL,
  "relationType1To2" TEXT NOT NULL,
  "relationType2To1" TEXT NOT NULL,
  "createdAt" REAL NOT NULL DEFAULT (unixepoch())
) STRICT
```

### Key Files
- [Database.swift](MySocialNetwork/Sources/Database.swift) - Database configuration and migrations
- [ContactRelationship.swift](Packages/Models/Sources/Models/ContactRelationship.swift) - Table model with `@Table` macro

## Development Workflow

### CRITICAL: Always Verify Builds

After making ANY code changes:

1. Run `tuist generate` if you modified dependencies or project structure
2. Build the project:
   - `mcp__XcodeBuildMCP__build_sim` (preferred)
   - Or `tuist build`
3. Fix all errors before marking task complete

**Never assume code is correct without building.**

### Adding a New Feature

1. Create a new package in `Packages/` with its own `Package.swift`
2. Define the TCA reducer with State, Action, and body
3. Create the SwiftUI view using `Store<Feature>`
4. Add the package dependency in `Project.swift`
5. Run `tuist generate`
6. Build to verify

### Adding Dependencies

1. Add the dependency in `Tuist/Package.swift`
2. Reference it in `Project.swift` or the package's `Package.swift`
3. Run `tuist generate`
4. Build to verify
